# 2026-09-21

## 新增 GitHub Actions：用测试 key 打生产包发布到 Releases
- 文件：`.github/workflows/build-release-debug.yml`（新建）
- 机制：app/build.gradle.kts 里 `release.signingConfig = debug.signingConfig`；当环境变量 `MIHON_GITHUB_RELEASE=true` 时，用 `storeFile/storePassword/keyAlias/keyPassword` 覆盖 debug signingConfig。workflow 用 keytool 现场生成标准 Android debug keystore（android/androiddebugkey/android，有效期 10950 天），因此不需要任何 secret。
- 构建命令：`./gradlew assembleRelease -Pdist=ci`、`./gradlew assembleFoss -Pdist=foss`（dist 由 gradle/build-logic/mihon/gradle/BuildConfig.kt 解析，决定 telemetry/updater/dependency-info）。
- 触发：workflow_dispatch（tag / 是否构建 FOSS / draft / prerelease / overwrite）+ push tags `v*`；版本号从 app/build.gradle.kts 的 versionName/versionCode 提取。
- 注意：fork 仓库（tokyai/mihon）需在 Settings → Actions → Workflow permissions 把 GITHUB_TOKEN 设为 Read and write，否则 release job 无法创建 Release。官方 release.yml 有 `github.repository == 'mihonapp/mihon'` 限制，在 fork 上不会执行。

## CI 排错记录（workflow 跑通前的三次失败）
1. `:app:compileReleaseKotlin` UNRESOLVED_REFERENCE `first` — ReaderViewModel.kt 漏 `import kotlinx.coroutines.flow.first`（只给 HttpPageLoader.kt 加了）。commit `36d50e40a`。
2. release job `failed to run git: not a git repository` — `gh release` 需要 git 仓库上下文，该 job 少了 `actions/checkout`。加 checkout（fetch-depth: 1）。
3. `Unable to resolve action actions/checkout@3d3c42e5aac5ba805825da76410c181273ba330` — 手打 SHA 写错，正确是 `3d3c42e5aac5ba805825da76410c181273ba90b1`（v7.0.1）。**教训：pinned SHA 必须整段复制，不要手打。**
- 另加了 `GH_REPO: ${{ github.repository }}` 作为 gh 的双保险。
- 推送经验：本机 Bash 直接 `git push` 报 "could not read Username"（环境里有 `GIT_TERMINAL_PROMPT=0`）；用 **`GIT_TERMINAL_PROMPT=1 git push origin main`** 可走 GCM 成功（会带一条无害的 schannel SSL 报错，但 push 实际生效，用 `curl api.github.com/repos/<repo>/commits/main` 核对 SHA）。PowerShell 工具的 git 输出常被吞，优先用 Bash。
- 本地编译验证仍未做（Gradle 9.7.1 wrapper 下载超时、沙箱不能写 ~/.gradle、JDK 17 vs toolchain 21）。
